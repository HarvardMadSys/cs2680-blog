{{/* Lays the post list out as a cascade: every card at its own height, each placed under whichever column is shortest so far. In a plain grid a card with a cover screenshot stretched the card beside it to match, which left a short card padded out with empty space as tall as the screenshot. Include it straight after the #post-list element. It runs there rather than on DOMContentLoaded so the cards are placed before the first paint. Placing in order, left column first on a tie, keeps the newest post top left and reading order roughly across then down. The DOM order is left alone, so tabbing and screen readers still go newest to oldest. Columns and gutter come from the stylesheet: `--columns` and `gap` on .post-list. At one column the grid already stacks cards at their own heights, so the script steps aside. Without JS the grid is what readers get, rows of equal height, which is the tidier fallback. The list is re-laid whenever it changes width (a resize, the breakpoint), a card changes height (a web font arriving), or its cards are swapped (post-filter.html writes its matches into the list). CSS has a native version of this, `display: grid-lanes`. When Chrome and Firefox ship it, this script can go in favour of one line in blog.css. */}}
