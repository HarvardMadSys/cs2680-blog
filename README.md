# blog.cs2680.com

The CS2680 student blog. Built with [Hugo](https://gohugo.io/). Students publish posts for
Assignment 1 (optional), Assignment 3 and Assignment 5.

Writing a post? See the [publishing guide](content/publish.md), also published at
`/publish/`. This file documents the site itself.

## Run locally

Requires Hugo **extended**, v0.164.0 or newer.

```bash
brew install hugo
hugo server -D          # -D includes drafts
```

Open <http://localhost:1313>.

## Post front matter

Required: `title`, `date`, `authors`, `summary`, `tags`, `draft`.

Optional:

| Field | Effect |
| --- | --- |
| `cover` | A file in the post folder, e.g. `"cover.webp"`. Shown at the top of the post, as the card thumbnail, and as `og:image` |
| `coverAlt` | Alt text for the cover. Empty when unset, i.e. treated as decorative |
| `coverCaption` | Caption under the cover on the post page |
| `toc` | Adds a contents list |
| `math` | KaTeX; on by default site-wide |
| `mermaid` | Enables Mermaid diagrams |

`_partials/cover.html` resolves `cover` once; the card, the post page and the meta tags all
use the result. Raster covers are re-encoded to WebP at three widths — 640px for the card,
1600px for the post page, 1200px for `og:image` — so a listing does not download full-size
screenshots. SVG files and absolute `http(s)` URLs pass through unprocessed. A post with a
cover gets `twitter:card: summary_large_image`; one without gets `summary` and no
`og:image`.

The card crops the cover to 16:9; the post page shows it whole.

## Styling

| File | Origin |
| --- | --- |
| `assets/css/course.css` | Verbatim copy of <https://cs2680.com/css/main.css>, fetched 2026-09-19 |
| `assets/css/blog.css` | Blog-only components |
| `assets/css/syntax.css` | Generated by `hugo gen chromastyles --style=github` |

**Do not hand-edit `course.css`.** It provides the palette, type stack, header, footer,
tables and prose styling. To update it:

```bash
curl -sL https://cs2680.com/css/main.css -o assets/css/course.css
# restore the header comment at the top of the file
```

It is vendored rather than linked cross-origin so the site builds offline and so a change
to the course site cannot restyle the blog mid-semester.

`blog.css` holds assignment tiles, post cards, the filter, bylines, tag pills, the pager
and the author index. Its colours are all tokens defined in `course.css`. It also overrides
`course.css` where the blog needs different behaviour — for example `.instructor-note >
summary`, which the course site sets in uppercase and the `collapse` shortcode needs in
normal case.

Bootstrap 5.3.3 and the Lato / Open Sans webfonts load from the same CDNs and pinned
versions as the course site, because `course.css` depends on them.

The header and footer markup mirrors `https://cs2680.com/header.html`. Navigation comes
from `[[menu.main]]` in `hugo.toml`.

## Design decisions

The blog uses the course site's palette, type and layout rather than a Hugo theme. The
header differs: the course site shows the SEAS lockup, the blog shows the MadSys mark with
its own name, course code and term. The SEAS lockup is in the footer.

`courseCode` and `courseName` are separate params. The header uses the code, which is all
that fits under the wordmark on a phone. The home page uses the name, since the code is
already in the title above it.

The menu has three items: Home, the current offering, and the course site. Assignments are
one click away from the front page and `/2026/`. The footer lists the pages the menu omits.

No public page states that a post is required, what it is worth, or when it is due.

## Icons

`static/favicon.svg` is a byte-for-byte copy of <https://cs2680.com/favicon.svg> — the
MadSys hexagon and square wave on a white rounded plate. Both sites use the same icon. If
the course site's favicon changes, copy it across rather than redrawing it.

The header mark uses the same two paths without the white plate, which the header bar
provides. `assets/madsys-logo.svg` carries the mark as an embedded 2048px bitmap and is not
used directly.

`static/favicon.png` (32px) is the fallback for browsers without SVG favicon support.
`static/apple-touch-icon.png` (180px, white square) is the iOS home-screen icon. Both are
rendered from `favicon.svg` at 512px and downsampled. Regenerate them if it changes.

## Behaviour notes

- **Future-dated posts are published.** `buildFuture = true`. Hugo otherwise hides
  future-dated content, which would drop a submission with a mistyped date.
- **Drafts are not published.** `draft: true` appears only under `hugo server -D`, with an
  amber stripe.
- **Posts are filed by year.** `content/2026/assignment3/jdoe/index.md` publishes at
  `/2026/assignment3/jdoe/`. Adding a later year does not move existing URLs.
- **Lists paginate at 20; the filter does not.** `_partials/post-filter.html` emits every
  card into a JSON island and swaps in matches, so the filter searches the whole collection
  rather than the current page. At eighty posts the island is about 7 KB gzipped.
- **Adding an assignment** means adding a section under the year with an `assignment` param
  in its `_index.md`, plus an archetype of the same name. The home page and offering page
  pick it up automatically; the tile row reflows.
- **`hugo new content` needs `--kind`.** The archetype is chosen from the first path
  segment, which is the year, so the publishing guide passes `--kind assignment3`
  explicitly.

## Rolling over to a new year

1. Create `content/2027/` and copy `content/2026/_index.md` into it with `year: 2027`,
   `term: "Fall 2027"`, `weight: 2027`.
2. Copy the `assignment*/_index.md` files across.
3. In `hugo.toml`, set `currentYear = "2027"` and `term = "Fall 2027"`, and point the `year`
   menu URL at `/2027/`.

`content/2026/` stays in place. Its URLs do not change and the home page lists it under
**Earlier offerings**.

## Deploying (Cloudflare Pages)

Connect the repository as a Pages project:

| Setting | Value |
| --- | --- |
| Production branch | `main` |
| Build command | `./build.sh` |
| Build output directory | `public` |
| Environment variable | `HUGO_VERSION` = `0.164.0`, on Production and Preview |

**`HUGO_VERSION` is required.** Unset, Cloudflare's build image installs Hugo 0.54.0, which
predates the `layouts/_partials` structure and renders pages with no layout instead of
failing. `build.sh` checks the version first and exits with instructions.

The custom domain is set in the Pages dashboard under **Custom domains**. No file in this
repository controls it; the former `static/CNAME` was a GitHub Pages mechanism and has been
removed.

If the dashboard offers no Pages option — Cloudflare has been moving new projects to
Workers — go to `https://dash.cloudflare.com/?to=/:account/workers-and-pages/create/pages`
directly.

### What `build.sh` does

1. **Checks the Hugo version** and fails with instructions if it is too old.
2. **Sets a preview-specific `baseURL`.** `hugo.toml` pins `https://blog.cs2680.com/`, and
   `_partials/head.html` emits absolute URLs for `og:url`, `rel=canonical` and the RSS
   feed. For any branch other than `main`, the script passes Cloudflare's per-deployment
   `CF_PAGES_URL` and `-e preview`.

`-e preview` changes three things:

| | production | preview |
| --- | --- | --- |
| `layouts/robots.txt` | `Disallow:` + sitemap | `Disallow: /` |
| CSS in `_partials/head.html` | minified, fingerprinted | plain `site.css` |
| Google Analytics | emitted if configured | never |

Run `./build.sh` with no Cloudflare variables set and it builds for production.

### Redirects

`static/_redirects` is copied to the root of the build output, where Pages consumes it
without serving it. It keeps the pre-2026 paths (`/assignment3/…`) working.

### Limitations

- **Pull requests from forks get no preview build.** Pages only builds branches in this
  repository, and the publishing guide has students work in forks. Reviewers see the diff
  but no preview link. A TF can fetch the PR branch and run `hugo server` locally, or the
  repository needs a GitHub Action to build previews.
- **Build quota.** The free plan allows 500 builds a month, one at a time. Pages' preview
  branch controls can narrow which branches trigger a build.

### Third-party requests

Bootstrap, KaTeX and Mermaid load from jsDelivr; webfonts load from Google Fonts. All are
version-pinned, with SRI where applicable. Cloudflare does not proxy them. These four are
what would need vendoring for a privacy or CSP review.
